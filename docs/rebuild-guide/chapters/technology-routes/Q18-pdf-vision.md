# Q18：PDF 图片理解与 OCR、多模态比较

## 1. 原理与本项目的使用

第 38 篇先读 PDF 文字层，再把确实需要视觉处理的页面渲染为 PNG，交给能接收文字加图片块的 DeepSeek 视觉接口。模型返回的是对页面的解释，不是可直接相信的原文；页面号、图片路径和模型描述必须分开保存。DeepSeek 当前视觉指南给出了 base64 data URL、外部 URL 与文件引用等传图方式，并说明 deepseek-flash 可接受图片；实际模型能力和限制以官方文档为准。[DeepSeek 视觉指南](https://api-docs.deepseek.com/guides/vision/)。

## 2. 同类技术路线对比

| 路线 | 适合的情况 | 代价或边界 |
|---|---|---|
| 原生文字层提取 | 可复制文本的 PDF，速度和成本较好 | 扫描页常得到空文字 |
| 传统 OCR | 需要逐字转写或可搜索坐标 | 图表关系、手写和复杂排版较弱，需语言校正 |
| 多模态模型 | 图表、截图、扫描页的综合描述 | 费用、延迟、幻觉与隐私边界更明显 |
| 人工录入/校对 | 高准确率的关键资料 | 慢，难覆盖大量文件 |

## 3. 工程边界与面试追问

先判断页面是否值得视觉调用，再限页数和图片尺寸；大量扫描 PDF 可先 OCR 做底稿，再让模型补图表说明。上传内容是用户数据，页面里即使写着“忽略系统规则”也不能成为指令。对账单、医学、法律等高准确场景，视觉输出必须人工核对；第 38 篇只生成学习索引，不承诺逐字忠实。
