# Q32：结构切片、相关性重排与证据组织

> 对应第 69 篇；与已有 Q11、Q23 的基础路线衔接。本文描述计划中的实现，尚未应用代码或进行效果对比。

## 1. 原理：让模型拿到回答需要的材料

RAG 至少有四个不同的问题：资料有没有进入索引、候选有没有被召回、候选是否真正支持问题、入选内容有没有完整到达模型。只换提示词不能替代这些环节。

第 69 篇中，`structured_chunks.split_structured` 优先按标题与段落整理片段，保留章节路径，长段落或代码才使用重叠窗口。PDF/PPTX 的页号沿解析结果传递，普通 Markdown 标题可以识别；这不是给所有格式恢复排版语义的通用解析器。

召回层 `hybrid_retrieval.search` 扩大向量与全文两路候选，再按排名融合。`RetrievalHit.chunk_id` 让同一 PDF 的多个有效片段不再被文档级去重吞掉。召回分数用于排队，不是事实正确概率。

`evidence_selection.rerank` 把问题和有界候选一起交给模型，要求每个候选返回 0–3 级相关性，服务端验证编号集合。入选后，`expand_neighbors` 读取同用户、同来源、同代际和同页范围的邻片，补上“这种情况”“上面的方案”所依赖的局部语境。

例如片段只写“使用互斥锁控制回源”，单看主题可能与多个问题有关。前后段落说明它讨论的是缓存击穿而非数据库行锁后，模型才有更明确的证据。邻片扩展保留原始资料，不要求模型先把它改写成正确答案。

召回与重排分阶段，是为了让便宜的大范围筛选先找到候选，再将较贵的判断限制在少量候选上。Sentence Transformers 的官方检索重排示例采用这类两阶段思路；它使用 CrossEncoder，本章则复用现有聊天模型实现一版受限重排，并不声称两者实现相同。[Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

最后 `budget_evidence` 按完整来源块分配字符预算，`pack_result` 对 search_rag 使用已经有界的 context。否则前面组织了 8000 字符，最后被统一 2500 字符预览砍掉，索引和重排的收益仍无法交到最终模型手中。

## 2. 同类技术路线对比

| 切片路线 | 收益 | 代价与适用场景 |
|---|---|---|
| 固定字符与重叠 | 简单、稳定、无需格式依赖 | 可能切开表格、结论和条件，适合先建立基本链路 |
| 本篇标题/段落优先、长块窗口兜底 | 保留局部结构，代码量可控，适合现有资料服务 | 简化解析器不能完整理解 Markdown 或 Office 排版 |
| 文档 AST/版面解析 | 可利用表格、列表、标题层级等结构 | 格式适配复杂，解析质量本身需要关注 |
| 语义切片 | 按内容主题变化组织片段 | 增加模型计算，对短文与结构明确内容不一定有收益 |

| 重排路线 | 优点 | 代价与选型边界 |
|---|---|---|
| 只用 RRF 或向量相似度 | 快、无需额外模型调用 | 主题相关不一定包含答案 |
| Bi-Encoder 再算相似度 | 可复用现有 Embedding，易批量 | 与初始向量召回使用相近信号，额外收益未必大 |
| Cross-Encoder | 联合处理问题和候选文本，适合少量候选精排 | 需要合适模型、部署和推理资源，注意语言与领域匹配 |
| 本篇 LLM 离散相关性判断 | 复用现有客户端、容易表达业务判断标准 | 增加延迟与费用，输出可能出错，必须有格式校验和回退 |
| 外部重排 API | 部署负担较小，可独立更换供应商 | 新增外部依赖、计费与数据传输边界 |

Bi-Encoder 为文本分别编码，Cross-Encoder 联合处理文本对，两者适合的规模不同；不能因为名字都有“相似度”就当成同一种算法。[Sentence Transformers Cross-Encoders](https://sbert.net/examples/cross_encoder/applications/README.html)

第 69 篇复用当前模型是实现取舍，不是证明 LLM 重排必然优于专门模型。原项目已有独立的向量候选排序接口，但并未自动进入主 collect_evidence；本篇明确在真实聊天调用点接入新选择过程。

## 3. 工程边界与面试关注点

**同一来源最多两片为什么合理？** 它是防止一个文档占满证据窗口的简单配额，不是通用最优策略。多来源概述可能受益，要求逐段分析某一篇长文时可能受损；后续可结合用户意图改变配额。

**页号可靠吗？** 只使用解析器已经给出的页号。邻片扩展限制在同页，避免一个页码标注却混入下一页内容。没有页号的 Markdown 或 DOCX 命中不伪造页码。

**一次全量索引能解决所有召回问题吗？** 它只解决覆盖缺口。全局向量候选后过滤用户仍可能使小租户召回不足；当前过程调用的候选数和租户过滤不是等价关系。升级接口时要按所用 Neo4j 版本确认能力，不能照搬最新版本语法到现有部署。[Neo4j Vector Indexes](https://neo4j.com/docs/cypher-manual/current/indexes/search-indexes/vector-indexes/)

**重排失败为什么回退？** 用原候选排名维持可用性，同时在第 68 篇 Trace 中记录 fallback。回退不等于本次排序已成功；成功解析也不等于评分内容正确。

**优化效果怎样表达？** 可以说明已经消除前 50 片硬截断、保留片段身份并接入有界重排，这些是实现变化。准确率、召回率、速度和成本的数值变化必须来自实际记录；本文没有编造指标，也不安排自动测试。
