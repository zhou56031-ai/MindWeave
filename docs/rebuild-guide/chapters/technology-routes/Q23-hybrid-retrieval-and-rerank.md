# Q23：混合检索、RRF 与候选重排

## 1. 原理与本项目的使用

第 46 篇把 Neo4j 全文候选和向量候选合并。全文擅长明确术语，向量擅长相近表达；两条路线的原始分数尺度不同，不能直接相加。RRF 按各自名次给分，把重复出现的 Chunk 累加，得到候选顺序。第 51 篇对少量已召回文本做二次向量排序，属于重排，不负责全库搜索。Neo4j 提供全文与向量索引机制，具体语义由本项目做融合。[全文索引](https://neo4j.com/docs/cypher-manual/5/indexes/search-indexes/full-text-indexes/)、[向量索引](https://neo4j.com/docs/cypher-manual/5/indexes/search-indexes/vector-indexes/)。

## 2. 同类技术路线对比

| 路线 | 适合的情况 | 代价或边界 |
|---|---|---|
| 字面 LIKE/contains | 小数据量和明确字符串 | 同义词、长问题召回弱 |
| 全文检索 | 精确词项、倒排检索 | 中文分词和同义表达需评估 |
| 纯向量 | 意义相近的段落 | 专有名词、数字、权限过滤可能失手 |
| 混合 + RRF | 两路互补，分数尺度不同时可融合 | 多索引、多次查询与评估成本 |
| 交叉编码器/专业 reranker | 小候选集更精细判别 | 额外模型延迟和资源 |

## 3. 工程边界与面试追问

先用当前用户范围取候选，保留来源 ID；模型生成前再检查证据是否仍存在。全局向量 top100 再过滤用户虽能防泄露，却可能使本用户低频资料永远进不了候选，需要专项召回测试。相似度百分比只可显示真正归一化的相似度，不能把 RRF 排名分当概率。固定问题集要比较 Recall@K、准确来源、延迟和故障回退，而不是只看最终回答是否流畅。
