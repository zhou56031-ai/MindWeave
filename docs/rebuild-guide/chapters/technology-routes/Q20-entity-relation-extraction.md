# Q20：实体关系抽取与受控结构化输出

## 1. 原理与本项目的使用

第 40 篇让 DeepSeek 从当前来源文本提取实体、关系，然后用 JSON 解析和 Pydantic 约束名称、数量、类型及端点。模型输出的合法 JSON 只是第一关；“A 属于 B”是否真的被原文支持，仍需证据句或人工评估。抽取任务应按来源分段、限制字符量，不能把整库正文一次发给模型。[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[Pydantic 模型](https://docs.pydantic.dev/latest/concepts/models/)。

## 2. 同类技术路线对比

| 路线 | 适合的情况 | 代价或边界 |
|---|---|---|
| LLM 结构化抽取 | 概念和关系种类变化多，少量样例即可启动 | 成本、延迟、幻觉和重复实体 |
| 规则/正则 | 固定格式、编号和术语 | 面对自然语言表达变化容易漏 |
| 专用 NER/关系模型 | 高吞吐、稳定领域数据 | 训练或标注成本、关系模式固定 |
| 全人工标注 | 高价值小规模资料 | 速度与规模受限 |

## 3. 工程边界与面试追问

把抽取结果视为“候选事实”，先验证端点存在、关系不自相矛盾，再写图。相同来源重抽应替换它拥有的边，不能累计重复；删除来源只清该来源的关系，不能误删别的来源仍引用的实体。工程问题是如何证明抽取好：建立固定文档集，按实体精确率/召回率、关系正确性、来源可追溯率评估。
