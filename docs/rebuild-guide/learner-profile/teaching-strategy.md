## 1. 已知基础直接使用

用户自述已掌握原第 02–04 章讲授内容（E007–E010）：Python 基础、模块与类、类型标注、异常、HTTP、JSON、协程与异步任务。后续代码直接使用，不重讲定义或安排基础自测。

具体机制的掌握范围以[知识地图](knowledge-map.md)为准。“未评估”表示没有反馈，不等于需要从最初级讲起。按有基础的读者写当前任务，遇到新机制结合代码解释，用户追问时再局部补充。

## 2. 最新要求决定讲解结构（E012）

用户明确要求：教我新建哪个文件夹，里面新建什么文件，放什么代码，文件有什么作用，关键代码如何发挥作用，并生动解释。

每篇围绕一个项目功能，按如下顺序推进：

1. 说明本步成果与真实起点，列出文件变化。
2. 给出需要创建的目录和命令，标明执行位置。
3. 逐个给出文件完整绝对路径（独立 text 代码块，方便复制）与操作类型；新建文件给完整代码，修改已有文件只给定位、前后 diff 和一段整体解释。
4. 每个后端文件后立即解释关键代码：谁调用、接收什么、改变什么、返回什么、失败怎样处理。
5. 用具体输入串起本步调用链，再给运行命令、预期结果和定位方法。
6. 核对最终文件与行为，说明下一步接着实现什么。

讲解围绕当前代码，不先堆一章理论再给代码，也不只交付代码让用户猜连接关系。

**文件变更标记（E013）**：编号步骤仅标【新增文件】【新增】【修改】【删除】或【运行验证】；阅读、搜索和只读定位写在操作依据或验收说明中，不单独编号。修改先给变更清单和可搜索定位，再展示完整改动的前后 diff，紧接一段生动、连贯的整体解释及验证；不重复展示整份修改后代码。源码中只用合法注释突出变化，JSON 等在外部标记；diff 仅作对照，不作为粘贴源码。

## 3. 后端怎样讲得生动而具体

新增框架机制或职责分工可以用短比喻说明，然后马上对应到函数、字段和执行时机。

例如讲路由与服务时，用本步真实的请求和函数，说明路由怎样拿到当前用户，服务怎样保存这位用户的笔记，数据库失败后响应如何变化。已知的字典、参数、return、await 不再逐行翻译。

新的数据库事务、请求验证、依赖注入、SSE、任务恢复、RAG 与 Agent 机制，仍需详细讲解，但在实现它们的文件中展开。复杂原理按需补充，不作为开始写项目的前置课程。

## 4. 前端由助手直接交付

将参考项目的前端源码直接接入复刻目录，完成运行和必要的接口适配，不再生成逐文件教程或要求用户照步骤编写。记录启动命令、验收结果和缺失的后端能力即可。实际提出的前端知识问题按该问题范围回答。

第 05 章后端环境已由助手准备（E011），有独立 .venv、依赖声明、锁文件、requirements.txt 和 Git 环境提交。正式复刻目录已代执行新版第 21–26 篇；第 23 篇解析文件原已存在并用于上传。前端直接复制参考源码，原第 17–22 篇前端操作教程已撤下。用户要求后续文档增加工程面试视角：解释当前设计的原因与取舍，以及并发、失败、边界等特定情况如何处理；不能只讲“有这个功能”。助手代执行与验证不算学习者已实践或掌握这些知识。下一阶段按路线图继续后端知识处理能力，不要求补做原第 02–04 章练习，也不依赖这些未创建的文件。
