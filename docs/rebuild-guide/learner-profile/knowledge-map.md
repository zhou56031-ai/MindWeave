## 1. 状态怎样理解

这里不计算总分或“掌握百分比”。每个知识点单独记录：

| 状态 | 判断依据 | 讲解方式 |
|---|---|---|
| 未评估 | 没有足够的自述或操作证据 | 按有基础的项目读者给完整操作，新机制结合当前代码解释 |
| 自述接触过 | 你明确说学过或用过，尚未展示理解 | 简短回顾，用当前问题确认理解边界 |
| 自述已掌握 | 你明确表示这些知识已经知道或掌握 | 直接用于项目示例，不重复基础教学；有新问题时局部补讲 |
| 能解释 | 你能用自己的话正确说明核心概念和边界 | 缩短基础定义，重点讲执行过程 |
| 提示下能应用 | 你在提示后完成相关操作，并能说明结果 | 给关键提示和检查点，减少代写步骤 |
| 能独立应用 | 你独立完成相应任务，解释结果并处理相关边界 | 聚焦设计取舍、排错和变化场景 |

“有待澄清”可附在任意条目，表示某个局部解释还需确认，不给整个人贴能力标签。某个小知识点的表现也不能代表整个模块都已掌握。

用户自评单独标记；助手依据实际回答或操作作出的判断也单独标记，二者不混写。

## 3. 当前讲解安排

1. 第 02–04 章整章已讲内容直接使用（E008–E010），不再重复标签、登记表等入门比喻或逐行翻译基础语法。
2. 后端仍详细解释业务数据流、函数之间的配合、设计原因和错误处理；新语法、新框架及未评估的主题按需要讲清楚。
3. 后端按 E012 给准确目录、文件、完整代码、职责和关键解释，再给运行验收。后续还要加入工程面试视角，回答设计原因、取舍及特定异常场景的处理。正式复刻项目后端已代执行新版第 21–26 篇；第 23 篇解析文件原已存在，不要求补做未创建的基础练习。
4. 前端直接交付参考源码、运行结果与接口契约，不再编写前端操作教程。
5. “未评估”不等于没有基础，不要求先考试；根据实际反馈局部调整。每次编写遵循[教程编写指导](../tutorial-writing-guide.md)和[讲解策略](teaching-strategy.md)。
